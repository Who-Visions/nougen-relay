## 19:47Z — Unpinned dependencies silently broke NouGenShards CI and nearly the live Space (2026-07-31)

Who-Visions/NouGenShards main went red with NO commit behind it. Two independent unpinned-dependency drifts, same shape:

1. LINT: ruff.toml documented "correctness-focused: pyflakes (F) + pycodestyle (E) with carve-outs" but only declared `ignore`, never `select`. CI does `pip install ... ruff` (unpinned), so the enforced ruleset was whatever ruff currently defaults to. A default shift produced 476 findings across untouched code (UP006 x127, UP045 x101, I001 x70, PLR/RUF/FURB/B/SIM). FIX: select = ["E4","E7","E9","F"] — ruff's own documented default. GOTCHA: bare "E" is WRONG, it pulls in E5 whose E501 line-length fires 433 times (tried it, CI proved it).

2. DEPENDENCY: pyproject had `mcp>=1.0` with no upper bound. CI resolved mcp 2.0.0, which MOVED `mcp.server.fastmcp` — imported by app.py and src/nougen_shards/mcp.py. ModuleNotFoundError. FIX: mcp>=1.0,<2.0. CRITICAL: this was not only CI — deploy-space.yml mirrors main to the HF Space (nougenai/NouGenShards) and the container installs from the same pyproject, so the NEXT SPACE REBUILD would have shipped a node that cannot boot.

LESSON: a green suite locally proves nothing when CI resolves dependencies fresh. Any unbounded dependency or unpinned linter is a change that can land without a commit. When CI is red and no code changed, suspect the resolver before the code. Also: a red main is not cosmetic — it blocks judgement on every open PR, including security fixes.

METHOD THAT WORKED: diff the failure SET between the PR branch and untouched main (identical set = introduced nothing), and read the CI log for which STEP fails — the failure moved from Lint to Run pytest after fix 1, revealing cause 2 which was otherwise invisible.

## 23:45Z — Antigravity lanes now ENFORCED via PreToolUse hook + two silent-no-op guard bugs

SHIPPED 2026-07-31 (whoart, commit fe32723 in Who-Visions/NouGenRelay): agy/Antigravity lanes are now GATED by the relay, not merely advised. 97 tests, lint clean.

## THE FULL JOIN FOR A NON-CLAUDE LANE = 3 PIECES
1. **MCP server** (tools to call) — 8 relay_* tools
2. **Skill** (when to call them) — ~/.gemini/config/plugins/<name>/skills/
3. **hooks.json PreToolUse** (what STOPS you) — the enforcement Claude gets from SessionStart hooks
All three ship in ONE Antigravity plugin: plugin.json + mcp_config.json + skills/ + hooks.json. Global: ~/.gemini/config/plugins/<name>/. Workspace: .agents/plugins/.

## HOOK SCHEMA (verified from Antigravity docs)
JSON on stdin, JSON on stdout, ALWAYS exit 0. PreToolUse in: {toolCall:{name,args}, stepIdx, conversationId, workspacePaths, transcriptPath, artifactDirectoryPath}. Out: {"decision": "allow"|"deny"|"ask"|"force_ask", "reason": str, "permissionOverrides": []}. Matcher is a REGEX on tool name. Edit tools: write_to_file|replace_file_content|multi_replace_file_content. Other events: PostToolUse, PreInvocation (can injectSteps!), PostInvocation (injectSteps + terminationBehavior), Stop (decision:"continue" prevents stopping).

## DESIGN: the decision ladder (do NOT just deny-when-unclaimed)
- another machine's ACTIVE claim overlaps -> **deny** (the real collision)
- nobody claimed it -> **ask** (nudge). Denying unclaimed work trains the operator to REMOVE the hook, and a removed hook protects nothing.
- this machine holds the claim -> **allow**
- ANY error/unparseable input/no .handoffs -> **allow** (fail OPEN, always)
Fail-open is deliberate: earlier the same day a well-meant guard proposal would have aborted a 10-commit rebase partway — worse than the problem it prevented.

## TWO SILENT-NO-OP BUGS — both looked like working guards
1. **Scraping CLI stdout.** The guard parsed `claim list` output. That output has box glyphs, CR (\r) line endings, and a `[mine  ]` padded field — parser returned [] and the guard ALLOWED EVERYTHING while appearing alive. FIX: read structured records via core._read_claims_from(root, None) + core.claim_is_active(rec). Records have machine/agent/goal/scope/status/created_utc/ttl_hours. NOTE core.foreign_claims() EXCLUDES your own machine — use _read_claims_from when you need both sides.
2. **Path separators not normalised.** Claims are written `src/lib.py`; Windows hands the hook `src\lib.py`. core._scopes_overlap does NOT normalise separators, so tokens never matched. FIX (hook-local): rel.replace("\\","/") before comparing. ⚠️ THE UNDERLYING core._scopes_overlap SEPARATOR BUG IS STILL THERE and affects any Windows machine claiming with backslashes — worth fixing in core.

LESSON: both bugs made the guard permissive while looking functional. A security/coordination guard must be tested by asserting it BLOCKS, never by asserting it doesn't crash.

## GOTCHA: bash backticks eat commit messages
`git commit -m "...`code`..."` in bash command-substitutes the backticks — commit fe32723 lost its inline examples. Use a heredoc for multi-line messages with code. Did NOT force-push to fix: two machines actively pull main, and that is exactly what blade's force-push guard exists to prevent. Cosmetic message damage < rewriting shared history.
