## Metameric Architecture Doctrine

Treat architecture search as equivalence-class discovery rather than feature accumulation. For implementation state x and observation function Phi, distinct implementations A and B are metamers only when Phi(A)=Phi(B) across the complete operational invariant vector. Equivalence is test-surface dependent. Matching benchmark accuracy alone is insufficient.

### Why this matters to NouGen
NouGen is heterogeneous by design: models, providers, machines, gateways, routes, memory stores, retrieval methods, cache states, and agent harnesses can change. The durable identity should live in verified behavioral contracts and invariants rather than any particular implementation. This creates a route for aggressive simplification: if two topologies remain functionally equivalent across every required invariant, select the cheaper, faster, simpler, more resilient representative.

### False metamer problem
A and B may look equivalent under Phi1=[accuracy] but diverge under Phi2=[accuracy, provenance fidelity, temporal fidelity, contradiction retention, epistemic justification, latency, cost, failure recovery, provider resilience, machine resilience, security boundaries]. Never promote equivalence until the observation function contains every invariant relevant to the production contract.

### Proposed lifecycle
1. Generate or identify structural variants.
2. Define explicit invariant vector and thresholds before comparison.
3. Execute candidates under matched conditions.
4. Project outcomes into invariant space.
5. Cluster candidates that appear behaviorally equivalent.
6. Attack equivalence using metamorphic transformations.
7. Eliminate false metamers.
8. Identify robust metamer classes.
9. Choose the minimum-complexity representative satisfying all thresholds.
10. Verify again before promotion.
11. Capture the decision, evidence, transformations, regressions, and provenance as durable memory.

### Metamorphic stress family
Test claimed equivalence under provider swap, model swap/downgrade, machine swap, prompt paraphrase, context compression, shard deletion, contradictory evidence injection, amendment/retraction injection, temporal displacement, stale context, network degradation, tool failure, gateway failover, cache cold start, token-budget reduction, multimodal evidence loss, duplicated evidence, fabricated authoritative evidence, and high-load concurrency.

For each transformation T_i, compare Phi(T_i(A)) and Phi(T_i(B)). Robust equivalence requires remaining inside defined tolerance across the transformation family, not merely scoring similarly on one static benchmark.

### Architecture implication
Do not equate sophistication with component count. If a 14-component architecture and a 5-component architecture are robust metamers across the full invariant vector, remove the nine unnecessary components. Simplification is safe only after equivalence survives adversarial and environmental transformations.
