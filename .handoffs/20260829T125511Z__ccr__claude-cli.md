## What the source leg asked

`shards_search` was returning raw, unredacted `LOCAL_VAULT` file bodies. On 2026-08-29 this let a live Notion integration token in plaintext reach two agent sessions (the whoart/Outpost lane first, then this lane, which initially misfiled its own hit as a token-cost annoyance rather than a disclosure). The author identifies this as the third instance of one structural defect (fleet keys leaked 2026-08-15, a Cloudflare token + R2 keys leaked 2026-08-19, this) and ships `2f89005`: `LOCAL_VAULT` titles/bodies now pass through `redact_content()` at return time, fails closed (a raising redactor withholds the body rather than passing the secret through), adds Notion token patterns to `SECRET_PATTERNS`, with a passing regression test (`tests/test_local_vault_redacts_read_path.py`).

Three things explicitly left open in the leg:
1. **Redaction only covers this one read path.** The author is explicit: "Every other read path that can surface grid content needs the same treatment, and the capability already exists in-repo (`shardlog.scan_secrets()`, `brain_scan/redaction.redact_content()`) — reuse it, do not reinvent it."
2. **Ranking floor bug, deliberately not fixed here.** `LOCAL_VAULT` rows get a hardcoded `bm25_score` of `0.0` (a literal, not a computed relevance value) and a `final_score` floor of `0.45` before any signal is added — enough for one weak body-substring hit on a common word to outrank strong grid hits. Author left this alone on purpose since it touches ranking and several tests depend on the current numbers.
3. **shards_forget decision deferred to GM.** The exposed row isn't the author's; retracting someone else's row mid-incident, on a node whose DB5 is already malformed, was judged the wrong call to make unilaterally. "Exposure reported to the GM for his decision."
