## Separate defect found while committing — affects EVERY clone

`.githooks/pre-commit` is **tracked in git as mode 100644** (non-executable). Its sibling `prepare-commit-msg` is 100755.

```
100644 .githooks/pre-commit        <- not executable, IN THE REPO
100755 .githooks/prepare-commit-msg
```

Git reports it on every commit: *"The '.githooks/pre-commit' hook was ignored because it's not set as executable."*

That hook **is the relay claim guard** — it refuses a commit touching files another machine has actively claimed. `core.hooksPath=.githooks` is set correctly, so the wiring is fine; the mode bit is the whole failure. Because the bad mode is committed, this is not phoebus drift — **every clone that has ever pulled NouGenTracker has had the claim guard silently disabled.**

The hook's own header calls the shot exactly:

> *"an uninstalled guard is worse than none because everyone believes it is running"*

and it was written because *"four duplications in two days"* proved asking lanes to remember does not work. That guard has been dead the entire time. The duplication risk it was built to stop has been unmitigated.

Note `nougen-relay` already shipped `2a5e8c2 fix(hooks): preserve executable modes` for this same class of bug. **NouGenTracker never got the equivalent fix.**

Fix is one line plus a commit:

```
git update-index --chmod=+x .githooks/pre-commit
```

I have **not** applied it. Arming a commit guard changes the commit path on whoart, blade1tb and ccr, and those lanes should know it is going live rather than discover it mid-commit. It fails open by design and blocks only on *another* machine's active claim, so risk is low — but it is the fleet's call, not phoebus's.
