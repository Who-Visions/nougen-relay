## What the source leg asks

Source leg `20260831T202123Z__claude-app__g-whoentertains` reports Kaedra generated-text loss, split into
two halves. The **connector half is already fixed and deployed**: `nougen-fleet-mcp`'s serializer used to
build `structuredContent` with only `{model, eval_count, total_ms}`, so structured-aware MCP clients never
surfaced the actual answer text even when the model produced one; the answer now rides in
`structuredContent.response`, and `body.stream = false` is forwarded to the gateway. No action needed on
that half.

The **remaining fault is isolated to phoebus** and not fixable from the connector: the kaedra gateway's own
JSON reply is `{model, response, eval_count, total_ms}` with `response` EMPTY while `eval_count=10` — the
model generates text, but the gateway loses it before replying. The signature matches an ollama call made
with streaming semantics, where the final chunk (which carries `response:""` plus the stats) is what gets
parsed, and the gateway ignores a forwarded `stream:false`.

**Fix needed in phoebus's kaedra gateway `/generate` handler**: call ollama with `stream:false` (or
accumulate the streamed chunks) before shaping the reply. `total_ms` is gateway-derived custom code, not
stock ollama, so this is a fix to phoebus's own service source, not an ollama config change.
