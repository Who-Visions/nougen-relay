# NOUGEN CLI WAR GAME

## Mission
Make NouGen CLI as conversationally versatile, persistent, tool-capable, resumable, autonomous, and user-facing as Claude Code, Codex, and AGY while preserving NouGen's unique advantages: local Ollama, OpenRouter, Hugging Face, Shards, Relays, fleet agents, Hardcade, and provider freedom.

This is not mainly a model-quality problem. Current Ollama, OpenRouter, and Hugging Face already expose enough primitives for strong agentic behavior. The missing layer is the harness: durable sessions, iterative act/observe loops, context assembly, tool policy, subagents, approvals, compaction, recovery, streaming events, and evals.

## TWO NEW NON-NEGOTIABLE LAWS FROM DAVE

### LAW 1: Claude always enters through NouGen Context
Claude must never start as a naked vendor session when invoked from the NouGen environment. Every Claude launch, resume, subagent, headless call, relay execution, or interactive session must receive a NouGen Context bootstrap first.

This context bootstrap should be generated by NouGen, not hand-maintained separately in every Claude session.

Recommended contract:

```text
nougen_context_bootstrap(session, cwd, agent, task)
  -> identity
  -> project rules
  -> active mission
  -> current branch/worktree
  -> unresolved relays
  -> relevant shard packet
  -> active claims
  -> recent decisions
  -> current fleet topology
  -> permission envelope
  -> provider/model capability notes
```

Then Claude receives only this bounded packet plus CLAUDE.md/project-local rules.

Implementation options, ranked:
1. Generate a compact `.nougen/context.md` or equivalent at session start and import it from CLAUDE.md.
2. Use Claude's `--append-system-prompt` / SDK system augmentation for ephemeral session context.
3. For programmatic/headless Claude, inject the generated context as the first structured message, then preserve the Claude session id.
4. Add a Claude startup hook / wrapper so calling `claude` inside NouGen transparently runs context assembly before Claude starts.

Do not duplicate the entire shard store into CLAUDE.md. CLAUDE.md should contain stable laws and an import/pointer to a generated bounded context artifact.

### LAW 2: NouGen Context must stay comfortably under 100k tokens
Dave explicitly wants shard-driven context streamlined below 100k to avoid the long-context penalty pattern currently seen in Claude usage.

Treat 100k as a HARD CEILING, not a target. Default working budget should be much lower.

Suggested budgets:
* 8k to 15k: ordinary chat / coding turn
* 20k to 35k: repo-scale work
* 40k to 60k: deep war game / architecture review
* 80k: emergency ceiling for unusually broad synthesis
* 100k: absolute governor, reject/compact before crossing

The context assembler must estimate tokens BEFORE provider invocation and compact or evict low-value material automatically.

# EXTERNAL RECEIPTS RESEARCHED 2026-09-02/03

## Claude Code patterns to absorb
Anthropic's CLI docs expose the mature harness shape directly:
* interactive REPL
* `-p` headless query mode
* `-c` continue latest conversation
* `-r` / `--resume` explicit session
* JSON and stream-JSON output
* `--max-turns`
* permission modes
* allowed/disallowed tools
* MCP configuration
* project/user memory through CLAUDE.md

Anthropic's long-horizon guidance explicitly recommends multi-window workflows where state is saved externally and context is compacted rather than forcing everything into one ever-growing prompt. It also recommends subagents when work is parallel, isolated, or independent, not for every trivial lookup.

This validates the NouGen direction: persistent external state + bounded prompt assembly + selective delegation.

## Hugging Face current primitives
HF's current Responses API already provides:
* event-driven semantic streaming
* built-in function tool orchestration
* remote MCP
* structured outputs
* reasoning controls
* multi-provider routing
* OpenAI SDK compatibility
* provider metadata including context length, pricing, tool support, structured-output support, latency, throughput, and free status
* automatic provider failover when using auto provider selection

This means HF should be treated as a backend adapter and provider router, not as the NouGen agent runtime.

## OpenRouter current primitives
OpenRouter now has the exact patterns NouGen should generalize:
* Responses API compatibility
* stable `session_id` for sticky routing and warm prompt caches
* advisor tool: cheap executor can selectively consult a stronger model
* subagent tool: frontier orchestrator can delegate self-contained mechanical work to cheaper workers
* tool calling / reasoning / structured output across many model families

Important OpenRouter cache receipt: stable `session_id` keeps follow-up turns routed toward the provider/model holding the warm cache. Changing the giant opening prompt every turn destroys this advantage. Therefore NouGen Context must have a stable prefix and a small dynamic suffix.

## Ollama current implication
Local models do not need to imitate Claude Code independently. They need to sit behind the same NouGen runtime. If a local model supports tools, structured output, and sufficient context, NouGen can provide the missing session/tool/approval/subagent machinery.

## OpenAI agent guidance
Current OpenAI guidance explicitly separates safe local work from external/destructive/costly actions. NouGen should encode the same boundary in its own provider-neutral policy layer.

Create one canonical control loop, e.g.:

`nougen/runtime/agent_loop.py`

State machine:

```text
USER_INPUT
  -> LOAD_SESSION
  -> ASSEMBLE_NOUGEN_CONTEXT
  -> CLASSIFY_INTENT
  -> SELECT_AGENT
  -> SELECT_MODEL_LANE
```

## 5. Shard Packet Protocol, the key to sub-100k operation
Do NOT give Claude raw `shards_recall` dumps across dozens/hundreds of shards.

Build a staged retrieval pipeline:

### Stage A: query decomposition
Turn task into 1 to 4 focused retrieval questions.

### Stage B: shallow recall
Fetch metadata/snippets only, e.g. top 8 to 15 each.

### Stage C: evidence selection
Score by relevance, recency, provenance, amendment/retraction status, utility marks, source diversity.

### Stage D: hydrate only winners
Read full content for maybe 3 to 8 truly necessary shards.

### Stage E: deduplicate
Collapse repeated history and near-duplicate shards.

### Stage F: structured compression
Produce a `ShardPacket`:

```json
{
  "question": "...",
  "facts": [],
  "decisions": [],
  "conflicts": [],
  "open_questions": [],
  "source_refs": [],
  "coverage": {},
  "token_count": 12400
}
```

### Stage G: hard budget gate
If packet exceeds configured budget, summarize locally and keep provenance refs so Claude can request expansion later.

### Stage H: lazy expansion
Claude gets `context_expand(ref)` as a tool. If it genuinely needs the full shard/file, it requests it during the loop instead of preloading everything.

THIS IS THE MAIN STRATEGY FOR STAYING UNDER 100K.

The runtime should behave more like virtual memory than a giant scrapbook: keep hot pages loaded, page cold memory in on demand.

## 6. Hierarchical memory
Separate memory classes:

### L0: turn buffer
Current conversational exchange.

### L1: working set
Current task facts, TODOs, files, tool results.

### L2: session summary
Compacted state across context-window refreshes.

### L3: project memory
Stable repo/project conventions and architectural facts.

### L4: Shards
Long-term evidence-backed memory.

### L5: Griot / archival history
Deep temporal reconstruction only when asked or required.

Do not query L4/L5 heavily on every turn. Most turns should live in L0 to L2.

## 7. Stable prefix + dynamic suffix for cache economics
Provider prompt caching rewards a stable opening context.

Design:

```text
[STABLE PREFIX]
NouGen laws
agent identity
project rules
fleet protocol
permission policy

[DYNAMIC SUFFIX]
current task
recent turns
selected shard packet
live repo state
tool observations
```

Hash the stable prefix. Reuse it until relevant rules actually change.

OpenRouter sessions should carry a stable NouGen `session_id` mapped 1:1 to the NouGen session so sticky provider routing/prompt caching can work.

Claude sessions should preserve Claude's native session id inside the NouGen session record rather than reinitializing Claude every call.

## 8. Compaction as a native operation
When token pressure rises, never simply truncate oldest messages.

Create a structured checkpoint:

```json
{
  "objective": "...",
  "decisions": [],
  "verified_facts": [],
  "files_touched": [],
  "commands_run": [],
  "failures": [],
  "open_questions": [],
  "next_actions": [],
  "shard_refs": [],
  "git_head": "..."
}
```

Cheap local model can draft. Deterministic code preserves exact ids/paths/status. Stronger model verifies only if required.

Trigger compaction by:
* predicted next-turn context > budget
* tool payload explosion
* 20 to 40 meaningful turns
* branch/task transition
* explicit `/compact`

## 9. Tool broker

```text

  git
```

Every tool declares:

Large tool outputs never flow raw into the model by default. Store artifact/result, return a digest + handle, and let model expand relevant slices.

## 10. Permission kernel
Separate sandbox from approval policy.

Suggested classes:
* READ_LOCAL: automatic
* WRITE_LOCAL_IN_SCOPE: automatic when user asked to build/fix
* EXECUTE_TESTS: automatic
* INSTALL_DEPENDENCY: configurable
* NETWORK_READ: automatic/configurable
* NETWORK_WRITE: confirm
* GIT_COMMIT: configurable
* GIT_PUSH: confirm unless explicit
* SECRET_ACCESS: special capability
* DESTRUCTIVE: confirm
* MONEY/PAID_API: budget-aware confirm or policy

The model never invents permission semantics. Runtime enforces them.

## 11. Advisor escalation
Build provider-neutral `advisor()`.

Pattern:
* local Ollama or cheap HF/OpenRouter runs ordinary loop
* uncertainty detector sees architectural risk / repeated failure / security issue / low confidence
* executor asks stronger model a narrow question
* stronger model returns guidance only
* cheap/local executor continues

This copies OpenRouter's excellent current Advisor pattern but keeps NouGen free to use Claude, GPT, Gemini, DeepSeek, Rhea, Kaedra, or future models as advisors.

Possible advisor triggers:
* two failed repair attempts
* architecture decision marked irreversible
* confidence < threshold
* multiple agents agree but evidence diversity is low
* security-sensitive change
* Xoah trigger conditions

## 12. Subagents
Build provider-neutral bounded children.

Use subagents for:
* independent repo searches
* test triage
* document summarization
* schema extraction
* parallel hypothesis testing
* platform-specific research

Do not give children the parent transcript automatically. Pass a task packet only.

Child context target: 5k to 25k.
Child receives explicit tools/capability budget.
Child returns structured result with evidence refs.

This protects the parent context and mirrors OpenRouter's current subagent isolation pattern.

# DONE WHEN
NouGen CLI can hold a natural multi-turn conversation, manipulate a codebase, use shards lazily, call tools, spawn bounded workers, consult stronger advisors, survive context-window refreshes and process restarts, switch providers without losing the task, recover from failed tools, resume the same session tomorrow, and render all of it through Hardcade or quiet CLI mode.

Claude specifically must always be attached to NouGen Context when used in this ecosystem, and ordinary shard-driven Claude turns must remain comfortably below 100k active context.

The strategic objective is NOT to clone Claude Code. It is to make Claude Code one lane inside a stronger provider-neutral NouGen control plane, while giving Ollama/OpenRouter/HF models the same session/tool/context machinery that makes premium coding agents feel powerful.
