## Research ingestion: arXiv 2608.26885 and the Configuration Is Cognition doctrine

### Core finding
Treat the workflow as the experimental and operational unit, not the model label. Deployed behavior is generated by a complete configuration: model + provider/version + prompt + input preparation + retrieval + context partition + batch topology + uncertainty policy + tools + interaction procedure + output contract + quality controls + verification + downstream decision rule. The paper's repeated screening runs show why this matters: strong aggregate agreement can coexist with meaningful item-level divergence, including consequential eligible records retained by only one run. The all-at-once context configurations also recovered fewer eligible records than corresponding file-batch configurations. Context capacity therefore does not imply context utilization, and batching topology can change capability.

### NouGen doctrine
CONFIGURATION IS COGNITION.
Do not benchmark 'GPT vs Claude vs Gemini vs Kaedra' as if model identity alone explains outcomes. Benchmark reproducible AgentConfiguration objects.

### Benchmarking rule
Every result should be attributable to a complete configuration. Avoid claims such as 'model X scored 94' unless the causal harness and processing topology are recorded. Preferred statement: 'Configuration H42 using model X, retrieval R3, partition P2, hydration H1, verification V4 achieved metric M under snapshot S.'

### Run stability
Single-run capability claims are insufficient for nondeterministic agents. For important candidate configurations, execute repeated matched runs and measure:
1. Aggregate performance mean and variance.
2. Overall run-to-run agreement.
3. Item-level disagreement set.
4. Critical/consequential disagreement set.
5. False-negative identity, not merely false-negative count.
6. False-positive identity where relevant.
7. Tool/action divergence.
8. Evidence-selection divergence.
9. Action-gate divergence.
10. Cost/latency variance.

Define consequence-weighted divergence. Variance should be weighted by what changed, not merely how often something changed. Formatting differences are low weight. A divergent destructive action, financial decision, canon mutation, credential operation, or irreversible tool call is high weight.

Conceptually:
D_c(H) = probability or weighted rate that repeated runs of configuration H disagree on consequential decisions.

A configuration with excellent average accuracy but high D_c is not operationally stable.

### False metamer connection
Two runs/configurations can appear equivalent under Phi=[aggregate accuracy/agreement] while diverging under expanded Phi=[critical miss identity, evidence provenance, action choice, consequence-weighted divergence, temporal fidelity, cost, latency, recovery]. Treat aggregate-only equivalence as candidate metamer status, never robust equivalence. Use the previously relayed metameric architecture lifecycle to attack the claim.

### Progressive hydration connection
The previous compression paper showed routing fidelity and reasoning fidelity need not be equal. This paper adds that reasoning topology matters too. Therefore optimize both REPRESENTATION RESOLUTION and CONTEXT PARTITION. Do not hydrate everything and then dump the hydrated payload into one giant context. Hydrate only selected evidence and organize it into processing units that preserve recall and contradiction visibility.

### Cost model
Track total lifecycle expenditure, not input tokens alone:
C_total = routing + retrieval + graph expansion + hydration + batch reasoning + synthesis + verification + retries + cache + tool calls.

Primary efficiency target should be verified useful outcomes per unit total cost/compute, subject to consequence-weighted stability thresholds.

### Risk-tier verification policy
Explore consequence-aware policies rather than universal autonomy:
- Low consequence: single configuration may act when confidence/knowability thresholds pass.
- Medium consequence: configuration + verification pass.
- High consequence: independent model/configuration or deterministic tool verification before action.
- Critical/irreversible: evidence graph + independent verification + explicit authorization policy, potentially human authorization where appropriate.

Human involvement is an independent verification pathway, not an oracle. Humans also vary with expertise, framing, fatigue, calibration, and uncertainty tolerance. Preserve provenance for human and model judgments equally.

### Independence requirement
When using multiple models/agents as verification, track whether their evidence and prompts are actually independent. Two agents reading the same fabricated authority may reproduce the same error. Agreement is only valuable relative to provenance and causal independence.

### Fleet router implication
Future routing should ask more than 'which model is strongest/cheapest?'
Target query:
Which VERIFIED CONFIGURATION produces the best expected outcome for this task class, consequence level, resource budget, evidence topology, and latency requirement?

This implies a configuration-performance registry derived from actual trajectories and verification, not static model reputation.

### HarnessLens connection
Treat changes in batching, partitioning, uncertainty policy, retrieval, hydration, verification, prompts, and action rules as harness evolution candidates. When a trajectory fails, diagnose the behavioral cause and modify the smallest causal component. Do not swap the model reflexively when topology caused the failure.

### GraphMemix connection
GraphMemix helps determine what complementary evidence should travel together. Use graph structure as one candidate partitioning signal. Evidence with relational dependence may belong in the same bounded reasoning unit even when semantic similarity is weak.

### Epistemic gate connection
Partitioning must not accidentally turn repeated derived claims into apparent independent evidence. Before action, collapse provenance families, surface contradictions, identify uncertainty, and evaluate knowability. More batches or more agents do not automatically mean more evidence.

### Metamorphic tests for configuration stability
Attack configurations with:
- repeated runs
- batch-order permutation
- equivalent prompt paraphrase
- provider/model swap
- context budget reduction
- cache cold/warm
- tool latency/failure
- evidence duplication
- contradictory evidence
- retracted/amended shard injection
- temporal displacement
- irrelevant-context inflation
- fabricated authority
- partial multimodal loss
- gateway failover
- concurrency/load

Measure whether required invariants survive.

### Highest-leverage experiments
1. Same model, same task, one giant context vs bounded batches, repeated 10+ times.
2. Same configuration repeated enough to quantify item-level and critical divergence.
3. Same evidence, different batch order, measure decision drift.
4. Progressive hydration + graph partition vs native full-context baseline.
5. Same model with different uncertainty policies, measure critical false negatives/positives.
6. Same task across providers using identical evidence graph and output contract, measure provider-specific instability.
7. Independent verification vs same-source echo verification.
8. Evidence duplication attack to test false confidence.
9. Fabricated authority attack from prior epistemic paper under each configuration.
10. Metameric comparison: identify two very different topologies with similar aggregate score, then attack them until equivalence survives or breaks.
