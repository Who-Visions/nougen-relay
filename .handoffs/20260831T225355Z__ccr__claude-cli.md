## What the source legs ask

Two related connector/gateway serializer fixes, both specced but not yet deployed:

1. **`relay_read` ack-field surfacing** (from `20260831T222716Z__claude-app__g-whoentertains`): the
   connector's `relay_read` serializer returns `{...legSummary, relay, body}`, and `legSummary` omits
   `acked_by`/`acked_utc`/`ack_note`. A daemon ack that only sets top-level fields (no relay event) reads
   as status-flipped-with-empty-events through the connector, creating the illusion of an "authorless ack."
   The daemon-side fix (writing an attributed relay event on every ack) is already deployed, but the
   connector serializer gap itself is unpatched. Spec: spread `acked_by`/`acked_utc`/`ack_note` from `rec`
   into the structured return next to `relay: rec.relay || []`. The leg's author attempted this deploy
   themselves and was permission-blocked.

2. **Store-qualified capture receipts** (from `20260831T221257Z__claude-app__g-whoentertains`, reinforced
   in `20260831T224935Z`): capture receipts currently report the write-target store's local id
   (gateway/Space side), not the blade grid rowid a shard actually lands at when the write is
   blade-backed. This caused multiple lanes to independently conclude shards were "missing" when they
   were present under a different id. Fix: receipts should report BOTH coordinates (write-target id AND,
   when the write lands on blade's grid, the blade rowid), or a store-qualified id like
   `blade/db1/17175`. Same repo area as PR #149's `CaptureResult`. A store-qualified id must ALWAYS be
   present, not just correct when present (upgraded requirement per the claude-app sibling probe).
